# ธรรมทะเบียน · s_passlist

เว็บสืบค้นทั่วไปพร้อมพื้นที่ผู้ดูแลสำหรับรายชื่อผู้สอบได้นักธรรมและธรรมศึกษา พร้อมอัปโหลด Excel ทุกภาค ทุกจังหวัด ทุกชั้น ทั้งมหานิกายและธรรมยุต แยกปี พ.ศ.

## ใช้งาน

1. ผู้ใช้ทั่วไปสืบค้นที่ `/` ได้โดยไม่ต้องเข้าสู่ระบบ ผู้ดูแลเข้าที่ `/admin` ด้วยบัญชี ChatGPT ที่ระบุใน `ADMIN_EMAILS` ฝั่งเซิร์ฟเวอร์
2. ดาวน์โหลดแม่แบบในหน้า **นำเข้าข้อมูล Excel** หรือใช้บัญชีเก่า .xlsx ที่มีหัวคอลัมน์ ชื่อ / นามสกุล
3. เลือกปี พ.ศ. และจังหวัดสนามสอบ หรือเลือก **อ่านจากไฟล์** เมื่อมีหลายจังหวัดในไฟล์เดียว (หนึ่งปีต่อไฟล์) ขนาดไม่เกิน 5 MB / 20,000 แถวรายชื่อ
4. เปิดโหมดอัตโนมัติ ระบบจะตรวจ จัดกลุ่ม นำเข้า และเผยแพร่เมื่อข้อมูลครบ ไม่มีข้อผิดพลาด/คำเตือน และยอดสถิติตรงกัน ถ้าไม่ผ่านจะพักเป็น draft เพื่อให้ตรวจทาน
5. สืบค้นด้วยชื่อ นามสกุล ฉายา วัด สำนักเรียน พร้อมตัวกรองภาค จังหวัด นิกาย ปี ประเภท และระดับ
6. ผู้ดูแลคลิกชื่อเพื่อดูแหล่งที่มาถึงชีตและแถว แก้ไขข้อมูล รวมถึงภาค/นิกาย/สำนักเรียน พร้อมเหตุผลและประวัติได้ ผู้ใช้ทั่วไปเห็นเฉพาะข้อมูลสืบค้นที่อนุญาต
7. หน้า **ชุดข้อมูลผู้ดูแล** ดาวน์โหลดต้นฉบับ/รายงาน ทำการนำเข้าต่อ เผยแพร่/พักเผยแพร่ เก็บออก หรือคืนชุดข้อมูล

รองรับนักธรรม/ธรรมศึกษา ชั้นตรี/โท/เอก หลายชีต หัวตารางซ้ำ บัญชีแบบพิมพ์เดิมที่มีหัวข้อแยกกลุ่ม และเซลล์ผสานของสำนักเรียน ไม่อ่านผลสูตร Excel เป็นข้อมูลชื่อ ไฟล์ .xls ต้องบันทึกเป็น .xlsx ก่อน

ข้อมูลหลักซ้ำและนามสกุลไม่ครบเป็นข้อสังเกตที่ต้องตรวจทาน ไม่ลบอัตโนมัติ ส่วนแถวที่ชื่อ ประเภท หรือระดับผิดพลาดต้องแก้ต้นฉบับหรือยืนยันแยกออก เก็บต้นฉบับและรายงานไว้เสมอ จังหวัดในคอลัมน์เดิมเป็นจังหวัดสังกัด แยกจากจังหวัดสนามสอบ เว้นแต่ผู้ใช้งานติ๊กยืนยันให้ใช้เป็นจังหวัดสนามสอบเมื่อไม่มีข้อมูลชัดเจนกว่า

## เทคโนโลยีและขอบเขต

- React + TypeScript ใช้ Next.js App Router API ผ่าน Vinext บน Sites / Cloudflare Workers
- ฐานข้อมูลถาวร D1 (SQLite) และ R2 เก็บต้นฉบับ Excel กับผลตรวจทาน
- fflate และ fast-xml-parser อ่าน/สร้าง XLSX แบบ synchronous บน server; ใช้ ExcelJS 4.4.0 เฉพาะ workbook model และทดสอบ; Drizzle schema และ migrations
- ใช้ Sites authentication และ allowlist `ADMIN_EMAILS` ฝั่งเซิร์ฟเวอร์สำหรับ `/admin` และ `/api/passlist`; `/api/public` อ่านเฉพาะ committed + published โดยใช้รายการคอลัมน์ที่อนุญาตเท่านั้น
- ซอร์สนี้ซิงก์จาก Sites เวอร์ชัน 38 (commit `46b64dea161cd43aff50d3b2079aa24396c1d600`) พร้อมชุดทดสอบที่ปรับหัวคอลัมน์ให้ตรงกับเว็บ ผู้ใช้อนุญาตเผยแพร่ข้อมูลอ้างอิงวัด/สถานศึกษาและข้อมูลสรุปจากไฟล์แนบสู่ GitHub สาธารณะแล้วเมื่อ 20 ตุลาคม 2569 ดูสถานะใน `DEPLOYMENT.md`
- แอปที่เผยแพร่ปัจจุบันยังใช้ Cloudflare D1/R2 และ ChatGPT sign-in ยังไม่ได้ย้ายฐานข้อมูลไป Supabase หรือเผยแพร่บน Vercel
- ยังไม่ใช่ PostgreSQL และยังไม่มีระบบมอบสิทธิ์ตามจังหวัด; มี public search API และผู้ดูแลตาม allowlist แล้ว
- ไม่มีรายชื่อผู้สอบตัวอย่างหรือข้อมูลบุคคลใน source/migration; ฐานข้อมูลผลสอบเริ่มว่าง ส่วนทะเบียนวัดอ้างอิงจากไฟล์ที่ผู้ใช้แนบจะติดตั้งใน D1 เมื่อผู้ดูแลเปิดระบบครั้งแรก

## ความถูกต้องและความปลอดภัย

Server ตรวจ ZIP metadata ก่อนขยาย จำกัดขนาดไฟล์และแถว ตรวจ schema แยกกลุ่ม ไม่เชื่อข้อมูลที่ client parse ใช้ parameterized SQL และตรวจ Origin สำหรับการเขียน ส่งออก CSV ป้องกันสูตร

Import เก็บ draft และ source ก่อน นำเข้ารายชื่อเป็นส่วนย่อย 400 แถวต่อคำขอ โดย ID แต่ละแถวคงที่และ retry ได้ รายชื่อจะถูกค้นพบเฉพาะเมื่อสถานะทั้งชุดเป็น committed เท่านั้น ใช้ SHA-256 กับ owner/จังหวัด/ปี ป้องกันไฟล์เดิมซ้ำ แต่ไม่ตัดชื่อเหมือนกันข้ามบัญชีอัตโนมัติ การเก็บออกเป็น soft archive พร้อม audit

## พัฒนาและตรวจสอบ

ใช้ Node.js ตาม engines ใน package.json และ pnpm ตาม lockfile

- `pnpm run dev` — preview ตามคู่มือ Sites
- `pnpm run db:generate` — สร้าง migration จาก db/schema.ts
- `pnpm exec tsc --noEmit` — ตรวจ TypeScript
- `node scripts/test-importer.mjs` — ทดสอบ importer
- `PASSLIST_REFERENCE=/absolute/path/to/2540.xlsx node scripts/test-importer.mjs` — ทดสอบไฟล์ต้นแบบในเครื่องโดยไม่บันทึกข้อมูลเข้าแอป
- build ตาม Sites workflow แล้ว `node tests/worker-smoke.mjs` — ทดสอบ Worker + D1/R2 จำลองแยก ไม่ใช้ production

ทดสอบต้นแบบปี 2540: พบรายชื่อที่ผ่านเกณฑ์ 9,589 แถว ครบ 6 กลุ่ม; แยกอีก 10 แถวที่มีลำดับแต่ไม่มีชื่อ (เช่น หมายเหตุเลขที่ข้าม) เป็น error; เลขลำดับทศนิยม 8 แถวถูกเก็บเป็นคำเตือน ไม่ได้โหลดไฟล์ต้นแบบเข้าฐานข้อมูล production

Worker smoke test ครอบคลุม authentication, isolation ระหว่างผู้ใช้, ติดตั้งทะเบียนวัด 44,704 แถวใน D1, เทียบชื่อ/พื้นที่/นิกาย, upload/preview, import ขัดจังหวะและทำต่อ, atomic visibility, idempotency, search, edit/audit, original download, CSV export, archive/restore และ cross-origin rejection

ไม่มี browser QA ใน environment รอบนี้ เนื่องจากไม่มี control-browser ตาม workflow ของ Sites ตรวจด้วย TypeScript, parser tests, build และ Worker integration tests


## การอ่านทุกภาค จังหวัด และนิกาย (รุ่น 2)

- แม่แบบเพิ่ม จังหวัดสนามสอบ / ภาค / นิกาย / ปี พ.ศ. ต่อแถว รองรับหลายจังหวัด หลายภาค สองนิกาย และทุกชั้นในไฟล์เดียวกัน
- อ่านขอบเขตจากคอลัมน์ หัวข้อ และชื่อชีต รองรับเลขไทย ตัวย่อ น.ธ./ธ.ศ. และ ม./ธ. ที่มีบริบทชัดเจน
- ภาคที่มีตัวเลข 1–18 และภาครวมตามต้นฉบับ เช่น ภาค 4-5-6-7 รวมถึงชื่อภาคที่กำหนดใน constants; ไม่สร้าง mapping จังหวัด→ภาคโดยคาดเดา
- นิกายเป็น มหานิกาย / ธรรมยุต เมื่อไม่พบจะเป็นค่าว่างพร้อมคำเตือน ไม่ตั้งเป็นมหานิกายโดยอัตโนมัติ ข้อมูลเก่าก็คงไม่ระบุจนกว่าจะตรวจยืนยัน
- ข้อมูลในแถวใช้ก่อนหัวข้อ/ชื่อชีต ส่วนภาค/นิกายเริ่มต้นที่เลือกใช้เติมช่องว่าง การเลือกจังหวัดแบบเจาะจงยังตรวจป้องกันแถวต่างจังหวัด ส่วนหลายจังหวัดต้องเลือกอ่านจากไฟล์
- เมื่อข้ามชีตจะเริ่มบริบทใหม่ เพื่อไม่ให้จังหวัด ภาค นิกาย หรือชั้นจากชีตก่อนติดมาด้วย
- ถ้ารูปแบบหัวตารางไม่ตรงกับชื่อคอลัมน์ที่รองรับ ต้องจัดลงแม่แบบก่อน ไม่อ้างว่ารองรับไฟล์ Excel ทุกรูปแบบ; ยังรองรับเฉพาะ .xlsx
- Migration 0001 เพิ่มเฉพาะขอบเขตและดัชนี ไม่เดาหรือเขียนทับภาค/นิกายของข้อมูลเดิม และ importer ยังคงทำงานต่อจาก draft รุ่นเก่าได้

การตรวจรอบนี้: TypeScript, importer 21 กรณีเมื่อมีไฟล์ต้นแบบ (20 กรณีหากไม่มี), ครอบคลุมข้อมูลจำลอง 924 แถว = 77 จังหวัด × 2 นิกาย × 2 ประเภท × 3 ชั้น โดยมีภาค 1–18 ครบ (ข้อมูลจำลองไม่ใช่ mapping จังหวัด→ภาคจริง), กระทบยอดแต่ละกลุ่มของปี 2540 เหมือนเดิม, ตรวจ migration รักษาข้อมูลเดิม และ Worker integration ทดสอบ upload→preview→commit→filter/export ตามภาค/จังหวัด/นิกาย/ประเภท/ชั้น รวมถึงแก้ภาค/นิกายพร้อม audit และ resume draft รุ่นก่อน

## อัตโนมัติ / ส่วนกลาง / สาธารณะ (รุ่น 3)

- อ่านรูปแบบหัวกระดาษตามภาพที่แนบ: บัญชีรายชื่อผู้สอบได้ | นักธรรม/ธรรมศึกษา | ตรี/โท/เอก; ในสนามหลวง | จังหวัด | เลขภาค 1–18 ที่แยกเซลล์; พ.ศ. | ปี
- อ่านปีจากหัวกระดาษ/แถวเมื่อเว้นปีในฟอร์ม และกระทบยอดคอลัมน์ สอบได้ จากตารางสถิติ หากไม่ตรงจะไม่เผยแพร่อัตโนมัติ (ต้องตรวจว่าเป็นยอดสถิติหลายระดับที่นับซ้อนกันหรือไม่)
- แยกส่วนภูมิภาคกับสำนักเรียนส่วนกลาง (วัด/คณะเขต) โดยอ่านคอลัมน์หรือหัวข้อสำนักเรียนที่ชัดเจน ไม่ใช้วัดที่เป็นเพียงสังกัดมาสร้างสำนักเรียนเอง
- ส่วนกลางที่มีชื่อวัด/คณะเขตชัดเจนไม่จำเป็นต้องสร้างภาค/จังหวัดขึ้นเอง ส่วนภูมิภาคต้องมีภาค 1–18 และจังหวัดจาก 77 จังหวัด นิกายต้องระบุเสมอก่อนเผยแพร่
- โหมดอัตโนมัติทำงานบนเซิร์ฟเวอร์: parse → validate → draft/source → insert ครั้งละ 400 แถว → committed + published ในขั้นสุดท้าย ไม่แสดงชื่อที่นำเข้าค้าง
- ข้อมูลไม่ครบ สูตรผิดตำแหน่ง ข้อมูลอาจซ้ำ หรือยอดไม่ตรง จะพักให้ผู้ดูแลตรวจ ไม่เดานิกาย ผู้ดูแลเลือกเก็บภายในเพื่อแก้ไขภายหลังได้ หรือเลือกค่าเริ่มต้น/แก้ไฟล์แล้วนำเข้าใหม่
- ข้อมูลเดิมมี visibility=internal ตาม migration 0002 ไม่เปลี่ยนเป็นสาธารณะโดยอัตโนมัติ ผู้ดูแลต้องตรวจและกดเผยแพร่เอง
- Public API ไม่คืน owner_id, batch_id, note, filename, sheet, source_row, fingerprint, audit และไม่มี endpoint ดาวน์โหลดต้นฉบับ/ส่งออกข้อมูลทั้งหมด
- Public search เรียงนิกาย → ภาคเชิงตัวเลข → จังหวัด → นักธรรม/ธรรมศึกษา → ตรี/โท/เอก → สำนักเรียน มีมุมมองแยกกลุ่มและตัวกรองวัด/คณะเขต ภาคเดี่ยวสืบค้นรวมภาคที่ระบุเป็นกลุ่มได้ เช่น ภาค 5 ค้นพบ ภาค 4-5-6-7 ด้วย
- ADMIN_EMAILS เป็น runtime secret เก็บเฉพาะฝั่งเซิร์ฟเวอร์ ค่าเริ่มต้นว่างคือไม่มีใครเป็นผู้ดูแล ไม่ให้ผู้สมัครหรือ user_metadata ยกระดับสิทธิ์เอง
- ทดสอบใหม่: ตัวอ่านตามภาพ 2 ประเภท, ส่วนกลาง 2 ชนิด, ยอดไม่ตรง/นิกายไม่ครบ, อัตโนมัติ 805 แถวครบหลาย chunk, ผู้ใช้ทั่วไปไม่เห็นข้อมูลภายใน, คอลัมน์ส่วนตัวไม่ติด projection, ดาวน์โหลด/เขียนโดยไม่ใช่แอดมินไม่ได้, เผยแพร่/พักเผยแพร่ และข้อมูลเก่าคงเป็นภายใน

## ทะเบียนสำนักเรียนส่วนกลาง (รุ่น 4)

- `lib/central-schools.ts` เก็บรายชื่ออ้างอิง 116 แห่งตามข้อมูลที่เจ้าของเว็บให้มา ไม่ได้อ้างว่าเป็นทะเบียนทางการที่ตรวจสอบจากภายนอก และไม่รับรองการสังกัดย้อนหลังทุกปี
- รหัส `กลาง ม.` หมายถึงส่วนกลางมหานิกาย และ `กลาง ธ.` หมายถึงส่วนกลางธรรมยุต รองรับในหัวข้อ ชื่อชีต และคอลัมน์นิกาย/ภาค/เขตข้อมูลต่อแถว
- ชื่อสำนักเรียนที่ตรงทะเบียนเติมส่วนกลาง กรุงเทพมหานคร นิกาย และชนิด (วัด/คณะเขต/คณะสงฆ์) เมื่อไม่มีข้อมูลนั้น โดยแยกจากวัดสังกัดของบุคคล ไม่เดาภาคจากจังหวัดและไม่จับชื่อคล้ายแบบ fuzzy
- จับคู่หลังตัดคำนำหน้า `สำนักเรียน`/`สำนักศาสนศึกษา` ช่องว่าง และทำขีดให้เป็นรูปเดียวกัน ไม่แก้คำสะกด ชื่อคณะสงฆ์จีนนิกายและอนัมนิกายคงหมวดมหานิกายตามรายการที่ให้มา
- นิกาย/จังหวัด/ชนิดที่ระบุขัดแย้งกับทะเบียนจะไม่ถูกเขียนทับ แถวนั้นพักเป็น error ให้แก้ต้นฉบับก่อนนำเข้า ส่วนชื่อที่ไม่พบทะเบียนยังเก็บไว้พร้อมคำเตือนเพื่อให้ตรวจประวัติ/ชื่อเก่าและนำเข้าแบบยืนยันเองได้ ไม่เผยแพร่อัตโนมัติ
- หน้า `/` และหน้าค้นหาผู้ดูแลเพิ่มตัวกรองส่วนกลาง ชนิด และชื่อสำนักเรียน หน้า `/` มีทะเบียนอ้างอิงที่ค้นหาแล้วเลือกสืบค้นรายชื่อได้ ตัวเลข 116 แห่งแยกจากจำนวนผู้สอบได้/สำนักเรียนที่มีผลสอบจริง
- หน้านำเข้าเพิ่มทะเบียนค้นหา/เลือกค่าเริ่มต้น และแม่แบบ `.xlsx` เพิ่มชีตทะเบียนส่วนกลางกับรายการเลือกชื่อสำนักเรียนและรหัสนิกาย อ้างอิงเดียวกับตัวตรวจฝั่งเซิร์ฟเวอร์
- ตัวกรองชื่อสำนักเรียนค้นข้อมูลเดิมที่ยังมีคำนำหน้า `สำนักเรียน` ได้โดยไม่เขียนทับข้อมูลเก่า ไม่มี migration หรือลงทะเบียนผลสอบจริงเพิ่มเติมในรอบนี้
- ตรวจ importer 29 กรณีรวมไฟล์ประวัติเดิม: ยังมี 9,599 แถวผู้สมัคร/placeholder และ 9,589 แถวชื่อครบใน 6 กลุ่ม ทดสอบทะเบียนครบ 116 × 6 กลุ่ม = 696 แถว พร้อมหัวกระดาษตามภาพ การขัดแย้ง ชื่อไม่ตรง และไม่เอาชีตอ้างอิงมาเป็นบุคคล

## นำเข้าก่อน ตรวจนิกายภายหลัง (รุ่น 5)

- หน้านำเข้าเปิดโหมด `deferSect` เป็นค่าเริ่มต้น: อ่านนิกายที่ชัดเจนต่อแถว/หัวข้อได้ทั้งสองนิกายในไฟล์เดียว ช่องว่างหรือค่าขัดแย้งเก็บเป็นว่างพร้อมข้อสังเกต โดยไม่กันชื่อที่ข้อมูลหลักครบออกจากการนำเข้าภายใน แถวที่ชื่อ ประเภท ชั้น จังหวัด หรือปีผิดยังต้องตรวจตามปกติ
- โหมดนี้บันทึกเป็น committed + internal และไม่เผยแพร่อัตโนมัติ แม้คำขอ commit จะส่ง publish=true มาด้วย ไม่มีการเปลี่ยนข้อมูล production ที่นำเข้าอยู่แล้วในรอบพัฒนา
- ชุด draft เดิมเลือก “นำเข้าเก็บภายในก่อน กำหนดนิกายในหลังบ้านภายหลัง” แล้วนำเข้าต่อได้ ไม่ต้องอัปโหลดใหม่ นิกายขัดแย้งเปลี่ยนเป็นข้อสังเกตเฉพาะ draft ที่ยังไม่เริ่ม insert; ไฟล์ต้นฉบับคงอยู่ใน R2
- เมนู “ตรวจนิกายตามวัด / พื้นที่” และปุ่ม “ตรวจนิกาย” ประจำไฟล์: กรองจังหวัดสนามสอบ ปี ไฟล์ วัด ตำบล อำเภอ และสถานะตรวจ แยกกลุ่มด้วย province/source_province/district/subdistrict/temple/school/jurisdiction/นิกายปัจจุบัน จึงไม่รวมวัดชื่อเดียวกันคนละพื้นที่หรือคนละนิกายโดยอัตโนมัติ
- ผู้ดูแลเลือกมหานิกายหรือธรรมยุต พร้อมเหตุผล/หลักฐาน แล้วบันทึกเฉพาะกลุ่มและตัวกรองที่แสดง มีจำนวนรายชื่อและจำนวนไฟล์ให้ตรวจบนหน้าบันทึก กลุ่มไม่มีชื่อวัดและสำนักเรียนต้องแก้รายชื่อก่อน ไม่ให้กำหนดนิกายรวมกลุ่มที่ไม่ทราบสังกัด
- เก็บ audit รายชื่อทุกแถวที่กำหนดนิกาย เปลี่ยน fingerprint ตามนิกายใหม่ และทำงานใน D1 transaction พร้อม snapshot guard ป้องกันการแก้ไขค้างระหว่างคำขอ จำกัดข้อมูลตาม owner และสถานะ committed ทั้ง GET/POST พร้อม admin authorization และ Origin check
- ผลตรวจยืนยันของผู้ดูแลมี sect_reviewed=1 ใช้ก่อนทะเบียนสำนักเรียนอ้างอิงสำหรับรายชื่อเหล่านั้น กรณีข้อมูลประวัติแตกต่างจากทะเบียนปัจจุบัน แก้นิกายรายบุคคลพร้อมเหตุผลได้ด้วย โดยไม่แก้ทะเบียนอ้างอิงทั้งระบบ
- Migration 0003 เพิ่มเฉพาะ subdistrict (ค่าเริ่มต้นว่าง) และ sect_reviewed (ค่าเริ่มต้น 0) ข้อมูลเดิมยังอยู่ แม่แบบเพิ่มแขวง/ตำบลท้ายตาราง และรองรับการแก้ตำบลในรายละเอียดรายชื่อ
- เมื่อกำหนดนิกายและข้อมูลจัดหมวดหมู่ครบแล้ว ผู้ดูแลกดเผยแพร่ประจำไฟล์ หากยังมีรายชื่อไม่ระบุนิกาย ระบบยังไม่เผยแพร่ทั้งชุด
- ตรวจ importer 31 กรณี รวมไฟล์ปี 2540 ยังพบ 9,589 รายชื่อที่ผ่านเกณฑ์เดิม; Worker integration ครอบคลุมนำเข้าภายในไฟล์รวมสองนิกาย/ค่ารวม/ช่องว่าง, draft เดิม, ตรวจกลุ่มสองตำบลและสองไฟล์, audit, stale count, owner isolation, non-admin, cross-origin, และการเผยแพร่หลังตรวจครบ ไม่ได้ตรวจผ่านเบราว์เซอร์จริงเพราะไม่มี control-browser ใน environment นี้

## ทะเบียนวัดและตรวจเทียบระหว่างนำเข้า (รุ่น 6)

- ใช้ข้อมูลจาก `Report_Temple.xlsx` ที่ผู้ใช้แนบ เก็บต้นฉบับ 44,704 แถวใน D1 ครอบคลุม 77 จังหวัด แบ่งเป็นมหานิกาย 39,723 แถว ธรรมยุต 4,938 แถว อนัมนิกาย 27 แถว และจีนนิกาย 16 แถว เก็บนิกายทุกค่าตามไฟล์โดยไม่แปลงสองรายการท้ายเป็นมหานิกาย/ธรรมยุต
- เมื่อติดตั้งรุ่นนี้ ผู้ดูแลเปิด `/admin` แล้วระบบทยอยนำเข้าทะเบียนเป็นชุดละ 500 แถว ทำซ้ำต่อจากแถวล่าสุดได้ หน้า “ทะเบียนวัดอ้างอิง” แสดงจำนวนจังหวัด นิกาย ที่อยู่ไม่ครบ และรายการชื่อ/พื้นที่ซ้ำ การอัปโหลดรายชื่อสอบจะเริ่มได้เมื่อทะเบียนติดตั้งครบ
- ระหว่างนำเข้า ระบบเทียบชื่อวัดหลังปรับช่องว่าง/คำนำหน้า “วัด” กับแขวง/ตำบล เขต/อำเภอ และจังหวัดสังกัดที่มีในไฟล์ โดยไม่ใช้จังหวัดสนามสอบแทนจังหวัดวัด ไม่แก้ข้อมูลสอบหรือตัดรายชื่ออัตโนมัติ
- ผลเทียบแยกเป็นพบตรงพื้นที่ นิกายขัดแย้ง นิกายอื่น รายการซ้ำ/นิกายกำกวม พบชื่อแต่ข้อมูลพื้นที่ไม่ครบ พื้นที่ไม่ตรง หรือไม่พบชื่อ ระบบแสดงข้อสังเกตในหน้าตรวจทานและรายงาน CSV ครบทุกแถว ดาวน์โหลดรายงานจากผลการนำเข้าหรือเปิดตรวจไฟล์ภายหลังได้
- คงรายการชื่อและพื้นที่ซ้ำไว้ตามแถวต้นฉบับ ไม่ fuzzy match คำสะกด และไม่ถือไฟล์นี้เป็นแหล่งยืนยันวันที่มีผลหรือสถานะทะเบียนวัดปัจจุบัน ให้ผู้ดูแลใช้ผลเทียบประกอบการตรวจและกำหนดนิกายเอง
- Migration 0004 เพิ่มเฉพาะตารางทะเบียนวัดและสถานะติดตั้ง ไม่มีข้อมูลทะเบียนอยู่ใน migration; ข้อมูลชุดตั้งต้นบีบอัดแยกจาก schema และนำเข้า D1 ผ่าน API ผู้ดูแลแบบทำซ้ำได้
- Worker smoke test นำเข้าทะเบียนจริงลง D1 แยกทดสอบ ตรวจจำนวน 44,704 แถวและ 77 จังหวัด และทดสอบรายการตรงพื้นที่ นิกายขัดแย้ง รายการกำกวม กับรายงาน CSV

## ปีเกิดและอายุ ณ ปีสอบผ่าน

- อ่านคอลัมน์ `อายุ` / `อายุ (ปี)` และ `ปี พ.ศ. เกิด` / `ปีเกิด` แยกจากปีสอบและพรรษา รองรับเลขไทย
- อายุจากบัญชีเป็นอายุ ณ ปีที่สอบผ่าน ไม่ใช่อายุในปีปัจจุบัน ถ้ามีเพียงอายุ ระบบคำนวณปีเกิดโดยประมาณ = ปีสอบ − อายุ ถ้ามีเพียงปีเกิด ระบบคำนวณอายุโดยประมาณ = ปีสอบ − ปีเกิด
- ไม่อนุมานวันเดือนปีเกิด ข้อมูลหายจะแสดงไม่ระบุ อายุไม่เป็นจำนวนเต็ม นอกช่วง 0–120 ปี หรือปีเกิดกับอายุแตกต่างเกินหนึ่งปี จะแจ้งให้ตรวจต้นฉบับ
- แสดงสองช่องในผลค้นหาและรายละเอียดทั้งประชาชนและผู้ดูแล โดยยังต้องใช้ชื่อและนามสกุลคู่กันสำหรับประชาชน ส่งออก CSV ของผู้ดูแลมีค่าพร้อมตัวบ่งชี้การประมาณ
- หลังอัปเกรด ระบบอ่าน Excel ต้นฉบับของชุดที่นำเข้าแล้วทีละชุดในงานเบื้องหลัง เติมเฉพาะช่องว่าง จับคู่ตามรหัส/ชีต/แถวต้นฉบับ ไม่แตะข้อมูลสอบ ชื่อ หมายเหตุ หรือรายชื่อในถังขยะ มี lease/cursor สำหรับทำต่อและบันทึก audit
- Migration 0007 เพิ่มเฉพาะ schema; ไม่มีการอ่าน Excel หรือ backfill ภายใน migration
- ตรวจสอบด้วย `node scripts/test-importer.mjs` และหลัง build ด้วย `node tests/exam-age-smoke.mjs` / `node tests/worker-smoke.mjs`

## พรรษา ณ ปีสอบผ่าน

- อ่านคอลัมน์ `พรรษา`, `อายุพรรษา`, `จำนวนพรรษา`, `ปีพรรษา`, `พรรษาที่`, `พรรษา (ปี)` จาก Excel โดยตรง รองรับเลขไทยและค่าศูนย์ ไม่คำนวณจากอายุหรือปีเกิด
- ใช้กับนักธรรมที่ไม่ใช่สามเณร ค่าว่าง/ไม่ถูกต้องแสดงไม่ระบุ และไม่เดาพรรษาของสามเณรหรือธรรมศึกษา ค่าที่ไม่เป็นจำนวนเต็ม นอกช่วง 0–120 หรือมากกว่าอายุที่ระบุ จะแจ้งข้อสังเกต
- แสดงคอลัมน์พรรษาต่อจากอายุ ณ ปีที่สอบผ่านในผลค้นหาและรายละเอียดของประชาชนและผู้ดูแล รวมถึง CSV และแม่แบบ Excel
- ชุดเดิมมีงานอ่านต้นฉบับแบบแบ่งช่วง เติมเฉพาะพรรษาที่ยังว่าง อ้างอิงรหัส/ชีต/แถวเดิม ข้ามถังขยะ รักษาข้อมูลอายุและค่าเดิมทั้งหมด มี lease/cursor/audit และแสดงสถานะในรายการชุดข้อมูล
- Migration 0008 เพิ่มเฉพาะ schema; ตรวจขั้นตอนอ่านไฟล์เดิมด้วย `node tests/vassa-smoke.mjs` หลัง build

## การแสดงสำนักเรียนและสังกัดในผลค้นหา

- ทั้งประชาชนและผู้ดูแลใช้ตารางร่วมกัน: จังหวัดสนามสอบแสดงเป็นสำนักเรียนคณะจังหวัด เช่น `คณะจังหวัดพิษณุโลก` ส่วนกลางยังใช้ชื่อสำนักเรียนวัด/คณะเขตเดิม
- นักธรรมแสดง `สังกัดวัด` จากวัดสังกัดของรายชื่อ และมีพรรษาหลังอายุ ธรรมศึกษาแสดง `สังกัดองค์กร/สถานศึกษา` จากสังกัดของรายชื่อและไม่มีคอลัมน์พรรษา
- ใช้ข้อมูลสังกัดของแต่ละรายชื่อ ไม่ใช้ชื่อสำนักเรียนแทนสังกัดที่หายไป ค่าที่หายแสดงไม่ระบุ ไม่มีการเปลี่ยนข้อมูลต้นฉบับหรือฐานข้อมูล
- ผลค้นหาที่มีสองประเภทในหน้าเดียวแสดงแยกสองตารางภายใต้การแบ่งหน้าเดิม เพื่อให้หัวข้อและจำนวนคอลัมน์ตรงกับประเภท ไม่ซ่อนหรือทิ้งรายชื่อ
- ตรวจ HTML ที่เรนเดอร์สำหรับประชาชน/ผู้ดูแลและตารางผสมด้วย `node scripts/test-results-display.mjs`

## เลข ปกศ. เลขไทย และการค้นชื่อบางส่วน

- คอลัมน์ `เลข ปกศ.` ในผลค้นหาและรายละเอียดทั้งสองฝั่งใช้ลำดับเดิมจาก Excel + ชื่อย่อจังหวัดสนามสอบ + ปีสอบ เช่น `ที่ พล ๑/๒๕๔๒` ไม่มีการออกเลขลำดับใหม่หรือสมมติเลขที่หาย เลขนี้เป็นการแสดงข้อมูลต้นฉบับ ไม่ใช่รหัสที่ต้องไม่ซ้ำข้ามชั้นหรือประเภท
- หน้าประชาชนรับชื่อและนามสกุลบางส่วน อย่างน้อยช่องละหนึ่งตัวอักษร ค้นแบบมีข้อความนั้นในทั้งสองช่อง รองรับคำนำหน้าและเลขไทย/อารบิกที่อยู่ในชื่อ Escape `%`/`_`/`\\` เป็นอักษรตามตัว ห้ามใช้ค้นรายการรวมโดยไม่ระบุชื่อคู่กัน และยังซ่อนข้อมูลที่ไม่เผยแพร่/ถังขยะ
- แสดงเลขไทยทั่วหน้าเว็บ รวมตาราง จำนวน ปี อายุ พรรษา วันที่ สถิติ รายงาน และเลขหน้า ช่องปี/เลขหน้ารับได้ทั้งสองรูปแบบ คงค่าเชิงตัวเลขและ ID/URL/ค่าตัวเลือกภายในไว้สำหรับการคำนวณและการทำงานของระบบ
- ผู้ดูแลมีปุ่ม `Excel เลขไทย` ในแต่ละชุดข้อมูล ดาวน์โหลดสำเนาค่าข้อมูลของต้นฉบับเป็นเลขไทย เก็บตำแหน่งเซลล์และรูปแบบสมุดงาน ค่าแคชสูตรที่มีผลลัพธ์เป็นสำเนาค่าคงที่ ต้นฉบับใน R2 ไม่ถูกเขียนทับและยังดาวน์โหลดได้ตามเดิม
- แม่แบบดาวน์โหลดและ CSV รายงาน/ผลค้นหาใช้เลขไทย ไฟล์ที่อัปโหลดรองรับเลขไทยสำหรับลำดับ ปี อายุ และพรรษา
- ตรวจด้วย `node scripts/test-importer.mjs`, `node scripts/test-results-display.mjs` และ Worker smoke หลัง build

## ตารางจังหวัดกับภาคตามข้อมูลผู้ดูแล

- ใช้รายการที่ผู้ดูแลให้เมื่อ 20 ตุลาคม 2569 ครบ 76 จังหวัด ภาค 1–18 (`lib/province-regions.ts`) กรุงเทพมหานครแยกเป็นส่วนกลาง ไม่มีการสมมติเลขภาคให้
- นำเข้า Excel แล้วเติมภาคเฉพาะช่องว่างจากจังหวัดสนามสอบ/สำนักเรียนคณะจังหวัด อ่านชื่อจังหวัดในช่องสำนักเรียนได้เมื่อเป็นชื่อจังหวัดหรือ `คณะจังหวัด…` โดยตรง ไม่ใช้จังหวัดที่ตั้งวัด/องค์กรแทนจังหวัดของสำนักเรียน
- ภาคที่ระบุในแถว หัวข้อ ชื่อชีต หรือค่าเริ่มต้นจะคงไว้ ถ้าไม่ตรงตารางจะแสดงข้อสังเกตเพื่อให้ผู้ดูแลตรวจ ไม่เปลี่ยนผลสอบเดิม ภาคแบบรวมคงเดิม และไม่แจ้งขัดแย้งถ้ามีภาคของจังหวัดนั้นรวมอยู่
- หน้าทะเบียนอ้างอิงรวมจังหวัด/ชื่อย่อ/ภาค ค้นด้วยชื่อจังหวัด ชื่อย่อ หรือภาคได้ รองรับเลขไทยและแสดงเลขไทย
- ร่างนำเข้าเก่าสามารถเติมภาคได้เมื่อเปิดตรวจ/นำเข้าต่อ งานเบื้องหลังเติมเฉพาะภาคว่างของรายชื่อเดิมที่ใช้งานอยู่ ข้ามส่วนกลางและถังขยะ ปรับ fingerprint พร้อม audit อย่างเป็นธุรกรรม มี lease/version และทำซ้ำได้
- Migration 0009 เพิ่มตารางสถานะงานเท่านั้น ไม่มี data backfill ใน migration ตรวจด้วย `tests/province-region-smoke.mjs` หลัง build
